Chapter 01

Introduction to Git & GitHub

Git is a distributed version control system created by Linus Torvalds in 2005. It tracks changes in your code over time, allows multiple developers to work simultaneously, and makes it possible to revert to any previous state of your project.

GitHub is a cloud-based platform built on top of Git. It hosts your Git repositories online, adds collaboration tools like pull requests, code reviews, issue tracking, and CI/CD pipelines through GitHub Actions.

📘 Key Difference Git is the tool you install locally. GitHub is the online service that hosts your Git repositories and enables collaboration.
🔀
Version Control
Track every change, who made it, and why — across all time.
👥
Collaboration
Multiple devs working on the same codebase without chaos.
🔁
Rollback
Instantly revert to any previous working state of your project.
🚀
CI/CD
Automate testing and deployment with GitHub Actions.

Chapter 02

Setup & Installation

Before using Git, you need to install it and configure your identity. This is a one-time setup that associates your commits with your name and email.

1
Install Git
Download from git-scm.com for Windows/macOS, or use your package manager on Linux.
2
Set your identity
Configure your name and email globally for all repositories.
3
Create a GitHub account
Sign up at github.com — free accounts get unlimited public and private repos.
4
Set up SSH or HTTPS auth
SSH keys let you push/pull without typing a password every time.
bash — Initial Git Configuration
# Verify installation git --version # Configure your identity (required) git config --global user.name "Your Name" git config --global user.email "you@example.com" # Set default editor (optional) git config --global core.editor "code --wait" # Set default branch name to 'main' git config --global init.defaultBranch main # Generate SSH key ssh-keygen -t ed25519 -C "you@example.com" # Copy public key to clipboard (macOS) cat ~/.ssh/id_ed25519.pub | pbcopy # View your config git config --list
💡 Pro Tip After generating your SSH key, add the public key to GitHub: Settings → SSH and GPG Keys → New SSH Key. Then test with: ssh -T git@github.com

Chapter 04

Creating Repositories

You can start a repository two ways: initialize a new one locally, or clone an existing one from GitHub.

bash — Initialize & Clone
# ── Method 1: Start fresh locally ── mkdir my-project cd my-project git init # ── Method 2: Clone from GitHub ── git clone https://github.com/username/repo-name.git # Clone into a specific folder git clone https://github.com/username/repo-name.git my-folder # Clone via SSH (recommended) git clone git@github.com:username/repo-name.git # Check repository status git status # View commit history git log --oneline --graph
📘 .gitignore Create a .gitignore file in your root to tell Git which files to ignore (node_modules/, .env, build artifacts, etc). GitHub provides templates at gitignore.io.
.gitignore — Common Patterns
# Dependencies node_modules/ vendor/ # Environment variables .env .env.local # Build outputs dist/ build/ *.o # OS files .DS_Store Thumbs.db # IDE files .vscode/ .idea/

Chapter 05

Commits & Staging

A commit is a permanent snapshot of your staged changes. The staging area (index) lets you craft exactly what goes into each commit — you don't have to commit everything at once.

bash — Staging & Committing
# Check which files changed git status # Stage a specific file git add filename.js # Stage all changes git add . # Stage parts of a file interactively git add -p filename.js # Commit with a message git commit -m "feat: add user authentication" # Stage and commit tracked files in one step git commit -am "fix: resolve login bug" # Amend the last commit (before pushing) git commit --amend -m "fix: updated message" # View what changed git diff git diff --staged
💡 Conventional Commits Use prefixes to make commit history readable: feat: (new feature), fix: (bug fix), docs: (docs), chore: (maintenance), refactor:, test:

Chapter 07

Remote & GitHub.com

A remote is a version of your repository hosted somewhere else — typically on GitHub. origin is the conventional name for your primary remote. You push changes up and pull changes down.

bash — Remote Operations
# Add a remote git remote add origin git@github.com:user/repo.git # List remotes git remote -v # Push branch to remote (first time) git push -u origin main # Push subsequent times git push # Pull latest changes git pull # Fetch without merging (inspect first) git fetch origin # Push a feature branch git push -u origin feature/my-feature # Delete a remote branch git push origin --delete feature/my-feature # Change remote URL git remote set-url origin git@github.com:user/new-repo.git
⚠️ Warning Never force push (git push --force) to shared branches like main. It rewrites history and can destroy teammates' work. Use --force-with-lease as a safer alternative.

Chapter 08

Pull Requests

A Pull Request (PR) is a formal request to merge changes from one branch into another. It's the heart of collaborative development on GitHub — enabling code review, discussion, and automated checks before merging.

1
Create a feature branch & commit
Always work on a dedicated branch, never directly on main.
2
Push your branch to GitHub
git push -u origin feature/branch-name
3
Open a Pull Request on GitHub
Go to your repo on GitHub → "Compare & pull request" → Fill in title and description.
4
Code Review & Discussion
Reviewers comment on specific lines, request changes, or approve the PR.
5
Merge the PR
Choose: Merge commit, Squash and merge, or Rebase and merge.
Merge StrategyWhen to useHistory
Merge commitPreserve all commits and branch historyFull history kept
Squash & mergeCombine all PR commits into one clean commitSingle commit
Rebase & mergeLinear history without a merge commitRewritten, linear

Issues & Projects

GitHub Issues are used to track bugs, feature requests, and tasks. They integrate deeply with pull requests — you can automatically close issues when a PR merges.

🏷️
Labels
Categorize issues: bug, enhancement, good first issue, help wanted.
🎯
Milestones
Group issues into sprints or versions with a due date.
👤
Assignees
Assign issues to specific team members responsible for them.
📋
Projects
Kanban-style boards for organizing and prioritizing work.
💡 Auto-close Issues In a PR description or commit, use keywords like Fixes #42, Closes #15, or Resolves #7 to automatically close issues when the PR merges to main.

Chapter 10

Merging & Resolving Conflicts

A merge conflict occurs when two branches modify the same line of a file differently. Git can't decide which version to keep, so it asks you to resolve it manually.

bash — Merge & Conflict Resolution
# Merge a branch into current git merge feature/my-feature # Rebase current branch onto another git rebase main # After resolving conflicts, continue rebase git rebase --continue # Abort a rebase git rebase --abort # Stash uncommitted changes temporarily git stash # Re-apply stashed changes git stash pop # Undo last commit, keep changes staged git reset --soft HEAD~1 # Discard changes in working dir git checkout -- filename.js
Conflict Markers in a File
<<<<<<< HEAD console.log("Hello from main branch"); ======= console.log("Hello from feature branch"); >>>>>>> feature/my-feature # 1. Edit the file to keep what you want # 2. Remove the conflict markers # 3. Stage the resolved file git add filename.js # 4. Complete the merge git commit

Chapter 11

GitHub Actions (CI/CD)

GitHub Actions is a powerful automation platform built into GitHub. It lets you run workflows automatically on events like push, pull request, or schedule. Common uses: testing, building, deploying, and linting.

📘 How it works Workflows are YAML files stored in .github/workflows/. They define triggers (events), jobs (virtual machines), and steps (individual commands or actions).
.github/workflows/ci.yml — Example CI Pipeline
# Runs on every push and pull request to main name: CI Pipeline on: push: branches: [ main, develop ] pull_request: branches: [ main ] jobs: build-and-test: runs-on: ubuntu-latest steps: - name: Checkout code uses: actions/checkout@v4 - name: Setup Node.js uses: actions/setup-node@v4 with: node-version: '20' - name: Install dependencies run: npm ci - name: Run tests run: npm test - name: Build project run: npm run build
🧪
Auto Testing
Run your test suite on every PR before it can merge.
🚀
Auto Deploy
Deploy to production automatically on merge to main.
🧹
Linting
Enforce code style and quality standards automatically.
📦
Publish
Publish npm packages or Docker images on new releases.
